# Gemini 笔记本会话展开

只做一件事：在 Gemini 左侧边栏里，给每个笔记本加一个展开箭头，点开就能直接看到
这个笔记本里的对话（不用再点进笔记本页面翻「过往对话」）。

没有文件夹、标签、提示词库、主题、统计等其他功能。

## 安装（Edge / Chrome）

1. 打开 `edge://extensions`（Chrome 是 `chrome://extensions`）。
2. 打开左下角（或右上角）的「开发人员模式」。
3. 点「加载解压缩的扩展」，选择本文件夹（`gemini-notebook-expand`）。
4. 打开 <https://gemini.google.com/>，侧边栏的笔记本前面就会出现展开箭头。

改了代码之后，在扩展管理页点一次「重新加载」，再刷新 Gemini 页面即可。

## 使用

- 点笔记本前面的箭头：展开/收起该笔记本的会话列表。
- 点列表里的会话：通过 Gemini 的页面内路由打开对话，不会重新加载整个页面。
- 按住 Ctrl/Cmd 点击，或使用鼠标中键：由浏览器在新标签页中打开。
- 展开状态在页面刷新后仍然保留（本次浏览器会话内）。
- 侧边栏收起时看不到笔记本区域，先点左上角「打开边栏」。

## 数据是怎么来的

扩展只读 Gemini 自己本来就会请求的「会话列表」接口（batchexecute 里的会话列表那一条），
以及这条请求的请求体里跟笔记本 id、分页上限有关的参数。不读对话内容，
不向任何外部服务发送数据。

拿到的数据分两种，靠请求里带没带笔记本 id 区分：

- **笔记本自己的列表**：笔记本页会专门为这个笔记本拉一次，请求体里写着笔记本 id。
  这份数据就是这个笔记本的会话，标记为「完整」，覆盖之前拿到的数据。
- **账号的近期会话总表**：这份数据里，每条会话都带父级字段（形如 `notebooks/<笔记本 id>`）。
  只有父级明确指向某个笔记本的会话，才会被算进那个笔记本；父级指向别的笔记本的归到
  那个笔记本；没有父级的是账号自己的会话，不归任何笔记本，不会混进笔记本列表。
  这份数据只标记为「残缺」，不会覆盖已经拿到的完整列表。

其他几点：

- 聊天页上这个接口只会返回当前这一条对话，属于残缺数据。
- 展开一个还没记录过的笔记本时，扩展会开一个后台标签页（不是前台，不打断你）
  让 Gemini 取回这个笔记本的完整会话列表，取到后立刻关掉标签页并渲染。
- Gemini 目前的分页上限是 10 条。如果某个笔记本的会话正好顶到 10 条，扩展会自动
  用更大的上限再问一次，避免只显示前 10 条。
- 会话列表按笔记本缓存在本地（`chrome.storage.local`），一周后重新获取。

## 已知限制

- Gemini 改版后如果笔记本列表的 DOM 结构变了，展开按钮可能需要跟着调整
  （相关代码集中在 `content.js` 的 `syncSidebar()` / `mount()`）。
- 展开一个陌生笔记本时会短暂出现一个后台标签页，这是让 Gemini 自己取数据的最省事办法。
- 会话地址里的账号前缀（`/u/0`、`/u/1`）取自页面的 `<base>` 和当前路径，
  所以切换 Gemini 账号后不用改代码。
- Gemini 侧边栏里的笔记本链接本身不带账号前缀，直接点它会跳到另一个 Google 账号，
  扩展只在自己渲染的会话链接上补前缀，不会去改 Gemini 自己的链接。
